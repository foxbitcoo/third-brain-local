# WPS 应用与权限

## 首版只申请两项

| 开放平台权限类型 | 搜索框输入 | 用途 |
|---|---|---|
| `user` | `kso.user_base.read` | 完成当前用户授权的基础身份范围 |
| `user` | `kso.mcp_message.readwrite` | 读取当前用户有权访问的会话与历史消息；不要求机器人逐群加入 |

在权限管理页面中，这两个 scope 可能同时出现 `app` 和 `user` 两行。**本地试用包两项都选择 `user`，不要选择 `app`。**本产品需要以每位试用者自己的 OAuth 身份读取其本人有权访问的会话；应用身份不能替代当前用户，也不应获得一份全体试用者共享的数据访问身份。

搜索时只输入表格中的原始 scope。不要输入或复制 `delegated:` 前缀：`delegated:kso.mcp_message.readwrite` 是本项目早期用于表达“用户委托”的内部配置写法，不是 WPS 开放平台权限搜索框里的真实名称。

首版不发送消息，因此不要求机器人应用权限。机器人、卡片、工作台、会议、文档、日历和通讯录都不属于本地需求验证包的前置条件。

`kso.mcp_message.readwrite` 的权限名称包含 `readwrite`。本版本代码只调用会话列表和历史消息读取工具，并未实现发送或修改接口；但授权范围的最终含义仍以 WPS 审批与授权页展示为准，安装者应在授权前核对。不要把“当前代码路径只读”误解成“平台权限名称本身只包含 read”。

## 操作顺序

1. 在 WPS 开放平台创建企业自建应用；
2. 在权限管理中用原始 scope 搜索上述权限，两项都勾选 `user`；
3. 配置回调 `http://127.0.0.1:4310/oauth/wps/callback`；
4. 创建应用版本，等待审批并发布；
5. 运行本地包，由实际试用者完成用户 OAuth；
6. 页面真实读到会话清单后，才能标记读取验证通过。

权限获批不等于 OAuth 完成；OAuth 完成也不等于所有消息分页可读。每一步分别记录。

## 安全边界

- App Key 和用户 Token 只在本地服务端使用，不能写入浏览器页面；
- 不读取或建议复制浏览器 `WPS_SID`；
- 每位试用者使用自己的 WPS OAuth，不能共享维护者或同事的 Token；
- 当前包只读，不会发送、撤回或修改任何 WPS 内容。
